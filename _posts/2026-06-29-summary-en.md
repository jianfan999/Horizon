## [CUDA Kernel Execution Path: CPU to GPU Deep Dive](https://fergusfinn.com/blog/what-happens-when-you-run-a-gpu-kernel/) ⭐️ 8.0/10

Fergus Finn's blog post provides a detailed walkthrough of the entire execution path when launching a CUDA kernel, from CPU code to GPU execution, covering driver commands, doorbells, and Queue Metadata Descriptors (QMDs). This fills a critical gap in most CUDA tutorials, which often stop at thread blocks and warps without explaining how the CPU driver submits work to the GPU. Understanding this path helps developers optimize kernel launch latency and diagnose performance issues. The article explains that the CPU driver writes commands into a pushbuffer, then writes a doorbell register to notify the GPU, which reads a QMD containing kernel parameters. It also notes that control codes are more complex than simple bits in a control word, involving table lookups.

hackernews · mezark · Jun 29, 13:11 · [Discussion](https://news.ycombinator.com/item?id=48718863)

**Background**: CUDA (Compute Unified Device Architecture) is NVIDIA's parallel computing platform and programming model. When a CUDA kernel is launched, the CPU driver must communicate with the GPU through a command queue. The process involves the driver writing commands to a pushbuffer, ringing a doorbell to signal the GPU, and the GPU fetching a QMD that describes the kernel configuration such as grid and block dimensions.

## [WATaBoy: JIT-compiling Game Boy to WASM beats native interpreters](https://humphri.es/blog/WATaBoy/) ⭐️ 7.0/10

WATaBoy is a project that just-in-time compiles Game Boy instructions to WebAssembly (Wasm) at runtime, and it achieves better performance than native interpreters when running in web browsers. This demonstrates that JIT compilation to Wasm can overcome the performance overhead of interpretation, enabling high-speed emulation in browsers, especially on platforms like iOS where JIT is restricted but browsers have an exception. The project uses WebAssembly Text Format (WAT) to compile Game Boy instructions dynamically. Notably, Firefox is about 25% slower than Chrome and Safari, likely due to differences in their Wasm runtime implementations.

hackernews · energeticbark · Jun 29, 15:02 · [Discussion](https://news.ycombinator.com/item?id=48720190)

**Background**: Just-in-time (JIT) compilation is a technique where code is compiled during execution, combining the speed of compiled code with the flexibility of interpretation. WebAssembly (Wasm) is a portable binary format designed for high-performance web applications, supported by all major browsers. Traditional emulators use interpretation or JIT to native code, but WATaBoy targets Wasm, leveraging the browser's optimized Wasm engine.
