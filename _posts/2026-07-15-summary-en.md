## [Firefox browser compiled to WebAssembly runs in a canvas element](https://developer.puter.com/labs/firefox-wasm/) ⭐️ 8.0/10

A port of the entire Firefox browser, including Gecko and SpiderMonkey, has been compiled to WebAssembly and rendered inside a <canvas> element, with end-to-end encryption via the WISP protocol and a novel WASM-to-JS JIT for speedup. This demonstration pushes the boundaries of WebAssembly by showing that a complex, full-featured browser can run entirely within another browser's WebAssembly runtime, potentially enabling secure, isolated browsing and new use cases like running a modern browser on locked-down devices. The project cost over $25,000 in Opus/Fable tokens for debugging and JIT research, and the WASM-to-JS JIT is an experimental optimization for site speedup. The WISP protocol provides TCP-over-WebSockets for end-to-end encryption.

hackernews · coolelectronics · Jul 15, 21:00 · [Discussion](https://news.ycombinator.com/item?id=48926939)

**Background**: WebAssembly (WASM) is a low-level binary instruction format that runs in modern web browsers at near-native speed. Building a full browser like Firefox in WASM is challenging because it requires porting the browser's rendering engine (Gecko) and JavaScript engine (SpiderMonkey) to compile to WASM, which typically involves significant work to handle threading, system calls, and performance. The WISP protocol is a lightweight method for proxying TCP and UDP sockets over a single WebSocket connection, enabling encrypted communication.

A technical blog post demonstrates running the Gemma 4 26B A4B model at approximately 5 tokens per second on a single, 13-year-old Xeon CPU without any GPU, using extreme inference optimizations. The Gemma 4 26B model is actually a Mixture-of-Experts (MoE) architecture with 4B active parameters per token, which reduces memory and compute requirements. The 5 tokens/sec speed is achieved through optimizations such as speculative decoding and careful memory management.

**Background**: Gemma 4 is a family of open LLMs from Google, released in 2026, available in dense and MoE variants up to 31B parameters. Running large models on CPUs is challenging due to limited memory bandwidth and lack of GPU acceleration. However, techniques like quantization, speculative decoding, and optimized inference frameworks have made CPU inference increasingly feasible. The 13-year-old Xeon likely uses DDR3 memory, which is far slower than modern GPUs, yet still achieves usable token rates.
